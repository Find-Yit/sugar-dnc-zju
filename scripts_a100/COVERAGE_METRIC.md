# 「可见表面覆盖率」mesh_pixel_coverage 指标定义（交付清单 A.5）

**脚本**：`scripts_a100/eval/render_mesh_views.py`（原位置 `repo/sugar-dnc-zju/scripts/eval/render_mesh_views.py`）
**输出字段**：每个 run 的 `outputs/metrics/meshvis_<run>.json` → `"mesh_pixel_coverage"`（按视角）
**汇总表**：`outputs/metrics/meshvis_summary_m.csv`

## 1. 定义

| 项 | 取值 |
|---|---|
| **视角** | 4 个固定视角，取自测试集内部序号 **0 / 8 / 16 / 24**，对应图片 **000001 / 000065 / 000129 / 000193**。测试集划分 `eval_split_interval=8`（`cam_list[i] for i%8==0`），共 28 个测试相机，与 hopper 侧 `eval_render.py` 完全一致。 |
| **相机** | `load_gs_cameras(..., load_gt_images=True)` → `CamerasWrapper(...).p3d_cameras[idx]`。必须 `load_gt_images=True`：3DGS 的 `cameras.json` 记的是 COLMAP 内参分辨率 1957×1091，而 `images/` 里的实际图是 979×546；为 False 时 SuGaR 会缩放成 1920×1070，与 RGB 渲染对不上。 |
| **光栅化器** | pytorch3d `MeshRasterizer` + `RasterizationSettings(image_size=(H,W), blur_radius=0.0, faces_per_pixel=1, max_faces_per_bin=200000)`。headless，不需要显示环境。 |
| **"覆盖"的判定** | 该像素的 `fragments.pix_to_face[0,...,0] >= 0`，即 z-buffer 命中了某个三角面（非背景）。等价于 `zbuf` 有有效值。**只看有没有面片挡住这条光线，不看颜色、不看法向、不看深度是否合理。** |
| **分母** | **979 × 546 = 534 534，即该视角的全部像素**，不做任何 mask、不排除天空、不排除图像边缘。 |
| **公式** | `coverage[idx] = hit.float().mean()`（代码原文 `coverage[idx] = float(hit_np.mean())`） |
| **四视角汇总** | `cov_mean` = 四个视角覆盖率的**算术平均**。 |

## 3. 为什么原版只有 92%：是**孔洞**，不是碎片缺失

**结论：是孔洞。** 证据链：

1. **孔洞的直接图证**：`results_a100/figures/fig_mesh_normal_compare.png` 第 1 行（原版 q=0.1）在**视角 00 与视角 16** 的天空 / 树冠区域有大片白斑（白＝该像素没有任何面片命中）。这两个视角恰好也是覆盖率最低的两个（0.8905 / 0.8776），而天空占比小的视角 08 / 24 有 0.9470 / 0.9649。覆盖率的高低与白斑面积一一对应。
2. **机制**：q=0.1 指 `--vertices_density_quantile 0.1`，即在 marching cubes 之前把密度处于最低 10% 分位的候选点/面片清洗掉。天空、远景树冠这些被高斯稀疏覆盖的区域密度最低，**整片被删掉，留下孔洞**，背景直接透出来。
3. **排除"碎片缺失"这一解释**：碎片本身只占极小的像素面积。实测（`results_a100/figures/fragstats_base_d10_q01.json`）原版 2094 个碎片分量在四个视角上只占 **1.175% / 1.950% / 0.876% / 0.344%** 的像素，即便把碎片全部删掉也只损失约 1% 覆盖率，解释不了 8% 的缺口。而原版的碎片面总数 28033，仅占 370284 面的 7.6%，且分散在已被最大分量遮挡的位置。
4. **反向验证**：`base_d10_q0`（仅把 q 从 0.1 改成 0，其余全同原版）覆盖率立刻从 91.997% 跳到 99.967%，面数反而**减少** 38515（370284→331769）。面变少而覆盖率上升，只能是"原来的空洞被封上了"，不可能是"补了更多细节"。

## 4. 指标的局限（必须与数值一起写进报告）

1. **它奖励"把洞封住"，不奖励"几何正确"。** q=0 之后 Poisson 在天空区域会生成**大平面封口三角形**（见 `results_a100/figures/fig_sky_closure_evidence.png` 中列），这些面片在物理上是错的——天空没有表面——但它们同样让 `pix_to_face>=0`，于是覆盖率满分。边界边由 38450 降到 11339（−70.5%）也有相当一部分来自这类封口面，而不是真的补全了几何。
2. **抓不到"背景整片缺失"这一类失败。** 失败案例 `m2largest_q0`（DBSCAN 只保留最大簇，把大量背景高斯整片剪掉）覆盖率仍有 **99.96%**，与最优组合几乎无差别——因为 Poisson 会用一个巨大的封闭曲面把整个场景包住，任何视角看过去都有面片。该失败只能靠法向图 / 深度图肉眼看出（`fig_failure_background.png`），或靠渲染 PSNR 抓。
3. **分母含天空**，天空占比在不同视角差异很大，因此**单视角数值不可跨视角比较**，只能同视角跨 run 比较。
4. **只判"命中/未命中"，不判深度是否正确。** 一个离相机很近的错误浮片与一个正确的远处表面，对该指标贡献相同。
5. **已经接近饱和。** 除原版外所有配置都在 99.95%–99.99% 之间，区分度不足 0.04%，**不能用它排序各改进方案**，只适合说明"原版存在孔洞，q=0 把孔封住了"这一件事。碎片数、最大分量占比、G1 才是有区分度的指标。

> 一句话：**mesh_pixel_coverage 是一个"孔洞检测器"，不是一个"质量分"。** 报告里引用 92%→99.98% 时必须同时说明第 1、2 条局限。
