# A100 侧交付清单（供 hopper 侧合并进 report.pdf 与 GitHub 仓库）

> 写给 A100 机器上的 Claude：请按本清单把材料打包，**推到同一个仓库 https://github.com/Find-Yit/sugar-dnc-zju 的新分支 `a100`**（不要动 `dnc` 分支），根目录放一个 `A100_DELIVERY.md` 说明每项对应的路径。截止：越快越好，hopper 侧硬截止 11:20，合并需要 30–40 分钟，所以请在 10:40 前推送；来不及的项标"未提供"，不要等齐。
> 原则：所有数字必须能追溯到你们机器上的日志/JSON；负结果与噪声内的差异照实标注；不要给"示意数据"。

## A. 必需（没有这些无法写进正式报告）

1. **指标汇总**：你们的 `outputs/metrics/summary.csv`（与 hopper 侧同列格式；若列不同，附列说明）以及每组 run 的 `geometry_<run>.json`、`render_<run>.json`（如有）、`extract_stats.json`、`train_stats.json`。
   至少覆盖：原版提取（baseline）、q0、M1+a、M2-B、q0+M2-B+M1+a（最优组合），以及扫参网格里的其余组。
2. **run 的来源与可比性说明**（一段文字）：
   - 用的 coarse 模型是你们自己重训的还是同一个 3DGS→coarse 链？3DGS 7k 与 coarse 15k 的 seed、命令、墙钟。
   - 原版提取的碎片数是 2137，与 hopper 侧 base_seed0 完全一致——请确认是巧合还是复用了 hopper 的模型/指标，若是重训请给你们自己的 baseline 全部指标。
   - 硬件（GPU 型号/数量）、torch/pytorch3d 版本、commit 哈希。
3. **代码改动**：M1+a（前景/背景分离自适应深度）、M2-B（提取前 DBSCAN 剪枝，含"保留所有 size≥阈值的簇"或 M2+a 贡献度评分，请写明用的是哪一种）、q0 参数化的 **git diff 或 .patch**，以及新增的命令行参数与默认值（默认必须=原版行为，请给证据：默认参数下的提取结果与原版逐位或噪声内一致）。
4. **确切命令**：每组 run 的完整命令行（含所有参数值）、日志路径、起止时间、提取耗时（原版 352 s vs 最优 240 s 的出处）。
5. **"可见表面覆盖率"指标的定义与脚本**：这是 hopper 侧没有的新指标（92.0% → 99.98%）。需要：定义（从哪些视角、什么判定为"覆盖"、分母是什么）、计算脚本路径、每组的数值、以及为什么原版只有 92%（是孔洞还是碎片缺失）。没有定义的指标不能进报告。
6. **M2-B 的剪枝统计**：DBSCAN 参数（min_samples、knn_percentile、eps 实际值）、剪掉的高斯数与比例、被剪簇的大小分布、是否有背景被整片剪掉的情况；若做了 min_samples / percentile 扫参，给整表。
7. **M1+a 的 D_fg / D_bg 实际取值**与估计中间量（quantile 距离、bbox、用到的高斯/点数），以及 "M1+b 表面点估密度零收益"的数字依据。
8. **可视化 PNG**（4 个固定测试视角，与 hopper 侧一致：测试集内序号 0/8/16/24，即图片 000001/000065/000129/000193）：原版 vs 最优组合的 mesh 法向图、碎片分量着色图（碎片用醒目色）、以及一张"孔洞 −71% 中天空封口大面片"的证据图（你们自己提到的，需要图证）。文件名里带 run 名。
9. **负结果与注意事项的原文**：Frosting 原样自动 D 零收益、M1+b 零收益、"前景卡车肉眼无差别、增益集中在背景"这几条的数字与图证；以及任何 [DEVIATION]（偏离计划之处）。
10. **SELF_CHECK / RUNLOG**：你们的自检文件（每个验收条目 + 实际值 + PASS/FAIL）与运行日志索引。

## B. 有则更好（不阻塞合并）

11. 泛化场景（train / playroom）上原版 vs 最优组合的几何指标。
12. M2-A（训练中剪枝）若跑了，给指标与 PSNR。
13. 网格渲染 PSNR（refined/textured 阶段）若来得及，给数值与命令；来不及就注明"未做"。
14. 提取端扫参的图（碎片 / G1 / 最大分量占比 随参数变化），PNG 300 dpi，中文标注；没有也行，hopper 侧可从 JSON 重画。

## C. 交付格式

- 分支 `a100` 目录建议：
  ```
  A100_DELIVERY.md            ← 每项对应路径 + 一段"结果一句话"
  results_a100/metrics/       ← summary.csv + 各 run JSON
  results_a100/figures/       ← PNG
  results_a100/notes/         ← SELF_CHECK、RUNLOG、ENV
  patches_a100/               ← M1+a / M2-B / q0 的 diff
  scripts_a100/               ← 覆盖率脚本、运行脚本、复现命令
  ```
- 不要放数据、权重、.pt、.ply（>10 MB 的都不要）。
- 推送后回复一句"已推送 a100 分支，commit <哈希>"。
