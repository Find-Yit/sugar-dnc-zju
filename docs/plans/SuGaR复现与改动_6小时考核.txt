2. 改动设计（预注册，已定稿；执行者不得改假设）
--------------------------------------------------------------------
名称：深度-法向一致性正则（Depth-Normal Consistency, DNC），加入 sugar_trainers/coarse_density.py 训练循环。
思路来源（报告中必须引用）：Huang et al., "2D Gaussian Splatting for Geometrically Accurate Radiance Fields", SIGGRAPH 2024
  提出的 depth-normal consistency loss。本工作把它移植到 SuGaR 的 coarse 阶段，属于借鉴已发表思路 + 自行实现，
  不复制任何 2DGS 代码。
自己的贡献点（报告要写清）：
  P1 移植到 SuGaR 的 3D 椭球表示：法向取最短 scale 轴（2DGS 是 2D 圆盘的固有法向），需处理法向朝向歧义；
  P2 与 SuGaR 原有 SDF 法向损失（sdf_better_normal_loss，采样点级别）的叠加分析：DNC 是像素级、跨高斯的约束，
     两者是否冗余/冲突要用实验回答；
  P3 λ 敏感性分析 + 失败案例（背景/天空/边缘）。
动机：SuGaR 用 SDF/density 正则把高斯压扁贴面，但每个高斯的法向只受采样点级别的 SDF 约束，相邻高斯法向可能互相
      不一致，导致 Poisson 输入法向噪声大、网格出现褶皱与漂浮碎片。让渲染法向图与渲染深度图的几何法向一致，
      可在像素尺度上强制相邻高斯共面。
实现（在 iteration > 9000（与 SDF 正则同期）时，每次迭代）：
  (a) 用现有 sugar.render_image_gaussian_rasterizer(point_colors=...) 渲染两张图：
      深度图 D（point_colors = 相机坐标 z；coarse_density.py 585–611 行已有此写法，直接复用，背景填 max_depth），
      法向图 N（point_colors = 每个高斯的世界系法向 = 最小 scale 轴经四元数旋转后的单位向量，逐高斯翻转符号使其
      朝向相机；渲染后在像素上再归一化）。
  (b) 用相机内参把 D 反投影成相机系点云 P(u,v)，用相邻像素中心差分 ∂P/∂u × ∂P/∂v 得几何法向 N_d，归一化，
      再用相机外参旋转到世界系（或反过来把 N 转到相机系，二选一，但必须同一坐标系）。
  (c) 有效像素掩码：D < 0.98·max_depth（排除未命中背景）；剔除图像边缘 2 像素；剔除深度梯度极大的像素
      （|∂D| > 相对阈值，跨物体边界）。
  (d) L_dnc = mean_valid( 1 − |cos(N, N_d)| )（绝对值消除符号歧义）。
  (e) loss += λ · L_dnc，λ 由新命令行参数 --dnc_factor 控制，默认 0.0；λ==0 时完全不进入 DNC 分支（不渲染 N、D），
      保证 baseline 代码路径与原版一致。
  (f) 每 100 iter 把 L_dnc 打进日志；每 1000 iter 保存 D / N / N_d / mask 的 PNG 到 run 目录（PIL）。
  (g) 新增 --dnc_start（默认 9000）便于冒烟测试，不改其他默认值。
可检验假设：
  H1（几何）：λ>0 时，mesh 碎片连通分量数 ↓，COLMAP 稀疏点→mesh 距离中位数 ↓，网格法向更平滑。
  H2（渲染代价）：测试视角 PSNR 变化在 ±0.5 dB 内；若下降更多，如实报告为代价。
  H3（叠加关系）：DNC 与原有 SDF 法向损失不冲突（训练中两者同时下降；若 L_dnc 不降或 SDF 法向损失上升，报告冲突）。
超参：λ ∈ {0.05, 0.2}（两个取值）。三组 run 命名：coarse_baseline / coarse_dnc005 / coarse_dnc02。
可选加分（仅当 09:00 前三组已完成且验收通过）：λ=0.2 + 2DGS 深度失真损失，作为第四组；或在 T&T 的 train 场景
  跑 baseline vs 最佳 λ 做泛化检查。这两项都不进入硬性交付，由 Fable 决定是否启动。
预期失败案例（报告要展示）：远景/天空深度差分法向噪声大 → 拉坏背景；物体边缘像素跨边界差分产生伪法向；
  细结构（Truck 的栏杆、天线）可能被过度平滑。
备选方案 B（仅当 DNC 实现在 60 分钟内跑不通时启用，须先向 Fable 报告）：
  改 sugar_extractors/coarse_mesh.py 的 Poisson 前主流程：对表面采样点做 kNN 法向一致性过滤
  （剔除与 16 近邻平均法向夹角 > θ 的点，θ ∈ {30°, 60°}），同样是"进入 mesh 提取主流程"的改动。

2b. 评测方案（数据集 + 指标定义，预注册）
--------------------------------------------------------------------
数据集：Tanks & Temples 的 Truck（来源：3DGS 官方打包 tandt_db.zip，含 COLMAP 稀疏重建 sparse/0）。
  规模：251 张图像，原始分辨率约 980×546（执行者在 ENV.md 里填实测值）。
  划分：3DGS 的 --eval 规则（llffhold=8：索引 %8==0 为测试）→ 32 张测试 / 219 张训练。三组 run 与 mesh 提取均用同一划分。
  3DGS 训练分辨率：3DGS 默认（宽 >1600 才降采样，Truck 不会降），三组一致。
  可选泛化场景：T&T 的 train（同 zip 内），仅在时间富余时跑。
所有指标由 $PROJ_ROOT/scripts/eval/ 下的脚本统一计算，输出到 outputs/metrics/，汇总到 summary.csv。
渲染指标（在 32 张测试视角上，用 coarse SuGaR 15k 的高斯渲染；另报 vanilla 3DGS 7k 作参考行）：
  M1 PSNR（dB，↑）：3DGS 官方定义（逐图 MSE 取 -10log10，再对视角求均值）。
  M2 SSIM（↑）：gaussian_splatting/utils/loss_utils.ssim（11×11 高斯窗）。
  M3 LPIPS-VGG（↓）：gaussian_splatting/lpipsPyTorch；VGG 权重下载失败则只报 M1/M2 并注明。
几何指标（Truck 无真值网格，用 COLMAP 稀疏点作为独立几何参考；对三组 mesh 用完全相同的 surface_level=0.3、
  decimation=200k 提取后计算）：
  G1 稀疏点→mesh 距离（↓）：取 COLMAP points3D 中 track 长度 ≥3 且落在前景 bbox 内的点，用 open3d
     RaycastingScene.compute_distance 算点到网格表面的无符号距离；报 mean / median / P90，单位为场景单位并同时除以
     相机空间尺度（sugar.get_cameras_spatial_extent()）给出相对值。
  G2 精度比例（↑）：G1 距离 < τ 的点占比，τ = 相机空间尺度的 0.5% 与 1%。
  G3 mesh 顶点→稀疏点最近距离 mean（↓，Chamfer 另一半，scipy cKDTree）；因稀疏点本身稀疏，只作参考并注明局限。
  G4 拓扑统计：顶点数、面数、连通分量数、最大分量面数占比（↑）、面数<100 的碎片分量数（↓，"漂浮碎片"），
     非流形边数、边界边数（open3d TriangleMesh 的 cluster_connected_triangles / get_non_manifold_edges）。
  G5 法向平滑度：相邻面二面角的均值与 P90（度，↓表示更平滑；过度平滑会吞掉细节，需结合图判断）。
训练代价指标：coarse 训练总墙钟（min）、每迭代平均耗时（ms）、峰值显存（torch.cuda.max_memory_allocated）、
  15k 时高斯数量。
可视化（三组并排，固定 4 个测试视角，视角索引由执行者选定并写进脚本）：
  V1 渲染图 + 与 GT 的 |误差| 热图（带色条）；
  V2 mesh 法向着色图（pytorch3d MeshRasterizer 渲染，headless）；
  V3 DNC 中间量（D、N、N_d、mask）；
  V4 失败案例特写（背景/边缘/细结构）。
指标方向与单位在 summary.csv 表头注明；报告中的所有数字只能来自 summary.csv 与 metrics JSON。
